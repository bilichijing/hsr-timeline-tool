## 1. 项目概述

### 1.1 项目目标

为本《崩坏：星穹铁道》玩家提供一款本地运行的排轴与伤害计算工具，支持：

- 队伍配置（角色 / 光锥 / 遗器 / 词条）
- 回合制排轴编辑（基于行动值 AV 系统）
- 战斗模拟与伤害计算
- 结果分析（DPS、伤害占比、轮次效率）
- 工程存档与分享

### 1.2 运行形态

- **本地桌面应用**，打包为 `.exe` 单文件分发
- 无需服务器资源，无 CORS 限制
- 数据从 `hsr.nanoka.cc` 拉取，本地缓存

### 1.3 与参考项目（wuwa-afyg-tool）的关系

- **参考**：数据层架构思路（manifest 版本管理、列表/详情分离、transform 提纯）
- **不参考**：业务逻辑（实时动作 vs 回合制，完全不同）
- **独立项目**：不共享代码，不共享数据源

### 1.4 关键差异认知

| 维度 | 鸣潮（参考项目） | 星铁（本项目） |
|---|---|---|
| 战斗模型 | 实时动作 | **回合制** |
| 时间轴 | 连续秒数 | **离散行动值（AV）** |
| 速度机制 | 无 | **核心机制**（10000/速度=AV） |
| 资源 | 共鸣能量 | **战技点（SP）**，上限 5 |
| Buff 时效 | 持续秒数 | 持续回合数 |
| 关键指标 | DPS | **轮次伤害 / 0T / 行动效率** |

### 3.2 Manifest 结构（实测）

`GET https://static.nanoka.cc/manifest.json`

返回多游戏统一 manifest，本项目只关心 `hsr` 字段：

```json
{
  "gi": { ... },          // 原神（忽略）
  "hsr": {
    "latest": "4.4.55",
    "available": ["4.4", "4.4.51", "4.4.52", "4.4.53", "4.4.54", "4.4.55"],
    "live": "4.4",
    "new": {
      "character": [1512, 1513],
      "lightcone": [21066, 22008, 23063, 23064],
      "relicset": [],
      "monster": [2022072, 2022082, ...],
      "item": [140630, 140631, ...]
    }
  },
  "ww": { ... },          // 鸣潮（忽略）
  "zzz": { ... },         // 绝区零（忽略）
  "nte": { ... }
}
```

字段说明：
- `latest`：最新版本号（用于拼接数据路径）
- `available`：所有可用版本（可用于版本切换）
- `live`：正式服版本
- `new`：该版本新增内容（用于"新角色"标记）

### 3.3 路径模式

#### 列表（轻量，含英文名与基础属性）

```
GET https://static.nanoka.cc/hsr/{version}/{entity}.json
```

| entity | 内容 | 示例大小 |
|---|---|---|
| `character` | 角色列表 | ~54 KB |
| `lightcone` | 光锥列表 | ~145 KB |
| `relicset` | 遗器套装列表 | ~92 KB |
| `monster` | 怪物列表 | ~456 KB |

> ⚠️ 列表只含英文名（`en` 字段），中文名在详情 JSON 里。

#### 详情（重型，含完整技能/星魂/属性）

```
GET https://static.nanoka.cc/hsr/{version}/zh/{entity}/{id}.json
```

示例：`https://static.nanoka.cc/hsr/4.4/zh/character/1001.json`（约 84 KB）

**版本管理**（简化版，无需 wuwa 的双路径策略）：

```python
import diskcache
import httpx

cache = diskcache.Cache('./cache')

def get_latest_version() -> str:
    cached = cache.get('hsr_version')
    if cached:
        return cached
    manifest = httpx.get("https://static.nanoka.cc/manifest.json").json()
    version = manifest['hsr']['latest']
    cache.set('hsr_version', version, expire=3600)  # 1 小时
    return version
```

**中文名获取**（列表只有英文，需两级查询）：

```python
async def get_character_zh_names() -> dict[int, str]:
    """返回 {id: 中文名} 映射，首次启动全量拉取并缓存"""
    cached = cache.get('character_zh_names')
    if cached:
        return cached
    version = get_latest_version()
    list_data = await fetch_json(f"/hsr/{version}/character.json")
    names = {}
    for char_id in list_data:
        detail = await fetch_json(f"/hsr/{version}/zh/character/{char_id}.json")
        names[char_id] = detail['name']
    cache.set('character_zh_names', names, expire=86400)  # 1 天
    return names
```

#### 时间轴控件设计

```
AV      0    50   100  150  200  250
角色A   ├───┼───┤────┼───┤
角色B   ├───────┤────┼───┤
角色C   ├───────────┤───┤
怪物     ├─────────┤────┤
         普攻  战技 终结技
```

- **横轴是行动值（AV）**，不是秒
- 每行一个角色/怪物，显示行动队列
- 操作块可拖拽排序

#### 模拟引擎主循环

```
输入：队伍配置 + 操作序列
输出：每个行动的伤害明细 + AV 时间轴

模拟循环：
  while 累计总行动值 < max_av (默认 300):
    1. 取行动队列下一个行动者（AV 最小者）
    2. 累计总行动值 += 行动者当前 AV
    3. 执行其操作（普攻/战技/终结技/怪物行动/阿哈时刻）
    4. 结算伤害、buff 生效/失效
    5. 更新 SP、能量、韧性
    6. 推进行动队列（所有单位 AV 减去本次消耗值，行动者重置）
```

**战斗结束条件**：以累计总行动值判定（默认 300），而非最大回合数。
每条行动日志（`ActionLog`）记录 `total_av` 字段，表示该行动结束时的累计总行动值。

#### 关键难点

- **Buff 时效结算**：回合制下"持续 2 回合"的精确定义
- **速度变化**：遗器套装、角色天赋会在行动中改变速度，需动态重排队列
- **击破状态**：韧性归零后进入击破状态，伤害加成不同
- **忆灵**：召唤物有独立行动条

#### 验收标准

- 能完整模拟一场总行动值达 300 的战斗
- 行动顺序与游戏内一致
- buff 叠加/失效逻辑正确
- 行动日志中每条记录都包含总行动值

## 6. 核心设计

### 6.1 行动值（AV）系统

星铁的核心机制。速度决定行动顺序。

#### 基础公式

```
行动值（AV） = 10000 / 速度
```

- 每个角色/怪物初始 AV = 10000 / 自身速度
- AV 最小的先行动
- 行动后 AV 重置为 10000 / 速度，其余角色 AV 减去已消耗值

#### 推条 / 拉条

- **推条**（延后）：AV += X * AV
- **拉条**（提前）：AV -= X * AV（下限 0）
其中X为行动延后/行动提前比例

#### 速度变化时的 AV 调整

速度变化时（如遗器套装、天赋触发），剩余 AV 按以下公式换算：

```
新行动值 = 原行动值 × 新基础行动值 / 原基础行动值 - 新基础行动值 × (提前% - 延后%)
```

其中：
- 基础行动值 = 10000 / 速度
- `提前%` / `延后%` 为本次速度变化同时附带的推拉条比例（无则为 0）

#### 怪物初始 AV

怪物初始 AV 也是 `10000 / 速度`，与角色同规则入队。

#### 实现要点

```python
from dataclasses import dataclass

@dataclass
class ActionEntry:
    unit_id: int
    speed: float
    current_av: float  # 距离下次行动的 AV

class ActionQueue:
    def __init__(self):
        self.entries: list[ActionEntry] = []

    def next_actor(self) -> ActionEntry:
        """返回 AV 最小的行动者"""
        return min(self.entries, key=lambda e: e.current_av)

    def advance(self, av_consumed: float):
        """推进时间，所有单位 AV 减少"""
        for e in self.entries:
            e.current_av -= av_consumed
        # 行动者重置
        actor = self.next_actor()
        actor.current_av = 10000.0 / actor.speed

    def apply_push(self, unit_id: int, av_delta_rate: float):
        """推条（正数延后）或拉条（负数提前）"""
        for e in self.entries:
            if e.unit_id == unit_id:
                e.current_av = max(0, e.current_av * (1 + av_delta_rate))
```

### 6.2 战技点（SP）管理

- 队伍共享，上限 5，初始 3
- 普攻 +1，战技 -1
- 某些技能可回复或消耗额外 SP

```python
class SkillPoint:
    MAX = 5
    INITIAL = 3

    def __init__(self):
        self.current = self.INITIAL

    def consume(self, amount: int = 1) -> bool:
        if self.current < amount:
            return False  # SP 不足
        self.current -= amount
        return True

    def recover(self, amount: int = 1):
        self.current = min(self.MAX, self.current + amount)
```

### 6.3 Buff 系统

#### 时效类型

| 类型 | 说明 | 失效时机 |
|---|---|---|
| `PERMANENT` | 永久 | 战斗结束 |
| `TURNS_SELF_START` | 持续 N 回合（自身回合开始） | 自身回合开始时 -1 |
| `TURNS_SELF_END` | 持续 N 回合（自身回合结束） | 自身回合结束时 -1 |
| `NEXT_ATTACK` | 下次攻击后 | 攻击命中后 |
| `ONCE` | 一次性触发 | 触发后立即失效 |

**TURNS_SELF_END 特殊规则**：若角色在自身回合内获得该类型 buff，则获得 buff 的这个回合结束时，对应 buff 的持续时间**不会减少**（即本次回合结束不扣减，从下一回合才开始扣减）。这意味着 buff 的"持续 N 回合"是从获得后的下一个自身回合开始算的。

实现要点：buff 记录 `applied_in_self_turn` 标志，回合内获得时置 True，首次 `tick_turn_end` 时跳过扣减并清除标志。

#### 叠加规则

| 规则 | 说明 |
|---|---|
| `NO_STACK_SAME_NAME` | 同名 buff 不叠加，刷新时效 |
| `NO_STACK_SAME_SOURCE` | 同源 buff 不叠加（如同角色两个技能） |
| `STACK_LIMIT_N` | 最多叠 N 层 |

#### 数据结构

```python
from enum import Enum

class BuffDuration(Enum):
    PERMANENT = "permanent"
    TURNS_SELF_START = "turns_self_start"
    TURNS_SELF_END = "turns_self_end"
    NEXT_ATTACK = "next_attack"
    ONCE = "once"

@dataclass
class Buff:
    id: str
    name: str
    stat: str              # 影响的属性（atk_pct, dmg_bonus, etc.）
    value: float           # 数值（百分比已 /100）
    duration_type: BuffDuration
    duration_count: int    # 回合数
    source_unit: int       # 来源角色 ID
    stack_rule: str = "no_stack_same_name"
    current_stacks: int = 1
```

### 6.4 伤害公式

星铁伤害分为 6 类：**常规伤害、击破伤害、超击破伤害、持续伤害、欢愉伤害**，共用抗性系数与防御系数。

---

#### 6.4.1 抗性系数

```
抗性系数 = 1 - 抗性
抗性范围：-100% ≤ 抗性 ≤ 90%
```

- 抗性由"基础抗性 - 减抗"得出，最终值钳制在 [-100%, 90%] 区间
- 弱点属性默认抗性 0%，非弱点属性默认抗性 20%

---

#### 6.4.2 防御系数

**角色攻击敌人时**（敌人等级超过 100 时按 100 计算；扑满须改为 `1.5 × 等级 + 30`）：

```
防御系数 = (角色等级 + 20) / [(角色等级 + 20) + (敌人等级 + 20) × (1 - 减防% - 无视防御%)]
```

**敌人攻击角色时**：

```
防御系数 = (10 × 敌人等级 + 200) / (10 × 敌人等级 + 200 + 角色防御)
```

减防与无视防御为加算关系，共同削减敌人防御占比。

---

#### 6.4.3 常规伤害

```
最终伤害 = 基础值 × 特殊独立乘区
         × (1 + 增伤%) × (1 + 易伤%) × (1 - 虚弱%)
         × (1 - 减伤1%) × (1 - 减伤2%) × (1 - 减伤3%) × ...
         × 抗性系数 × 防御系数 × 暴击区
```

各乘区说明：

| 乘区 | 说明 |
|---|---|
| **基础值** | `攻击力 × 倍率`，攻击力可替换为生命值/防御力等（视技能而定） |
| **特殊独立乘区** | 如最终伤害加成等极为特殊的效果，独立乘算 |
| **增伤** | 描述中带有"我方造成的伤害提升 X%"的效果（属性增伤、通用增伤均属此区） |
| **易伤** | 描述中带有"目标受到的伤害提升 X%"的效果 |
| **虚弱** | 描述中带有"虚弱"的特殊效果，独立乘区 |
| **减伤** | 描述中带有"目标受到的伤害降低 X%"的效果 |
| **暴击区** | `暴击率 × 暴击伤害 + (1 - 暴击率)`，不暴击时为 1 |

减伤规则：
- **多个减伤为乘算**：例如两个 50% 减伤 ≈ 一个 75% 减伤（0.5 × 0.5 = 0.25）
- **所有减伤乘算后不低于 1%**（下限保护）
- **敌方未被弱点击破时，必定带有 10% 减伤**（击破后此减伤消失）

---

#### 6.4.4 击破伤害

角色击破弱点时，造成的击破伤害：

```
击破伤害 = 击破基础值 × 属性倍率 × 特殊独立乘区
         × (1 + 易伤%)
         × (1 + 击破特攻%) × (1 + 击破增伤%)
         × (1 - 减伤1%) × (1 - 减伤2%) × ...
         × 抗性系数 × 防御系数
```

击破基础值与属性倍率：

```
击破基础值 = 3767.55 × (韧性上限 / 40 + 0.5)
```

| 属性 | 属性倍率 |
|---|---|
| 火、物理 | 2.0 |
| 风 | 1.5 |
| 冰、雷 | 1.0 |
| 量子、虚数 | 0.5 |

关键规则：
- **击破伤害不受常规增伤和虚弱影响**（无增伤区、无虚弱区）
- 但有专门的**击破特攻**和**击破增伤**两个独立乘区
- 击破伤害仍受易伤、减伤、抗性、防御影响

---

#### 6.4.5 超击破伤害

超击破伤害需要通过**角色技能效果**触发，而非自动产生。

**触发条件**（由技能描述决定）：
- 一般情况：攻击**处于弱点击破状态**的敌方目标时触发
- 特殊情况：某些技能效果允许在未击破状态也触发（如大丽花战技"结界持续期间，敌方目标未处于弱点击破状态时承受的削韧值也能够转化为超击破伤害"）

**触发示例**（大丽花天赋）：
> 【共舞者】攻击处于弱点击破状态的敌方目标后，会将本次攻击的削韧值转化为 1 次 60% 的超击破伤害。

**超击破倍率**由触发源（天赋/光锥/技能效果）提供，不同来源倍率不同。

```
超击破伤害 = 超击破基础值 × 超击破倍率 × 特殊独立乘区
           × (1 + 易伤%)
           × (1 + 击破特攻%) × (1 + 击破增伤%)
           × (1 - 减伤1%) × (1 - 减伤2%) × ...
           × 抗性系数 × 防御系数
```

超击破基础值：

```
超击破基础值 = 3767.55 × 实际削韧值 / 10
```

- 与普通击破伤害相同的乘区结构（不受常规增伤和虚弱）
- 基础值取决于**实际削韧值**（本次攻击削减的韧性），而非韧性上限

---

#### 6.4.6 持续伤害

角色造成的持续伤害（DoT，如触电、灼烧、裂伤等）：

```
持续伤害 = 基础值 × 特殊独立乘区
         × (1 + 增伤%) × (1 + 易伤%) × (1 - 虚弱%)
         × (1 - 减伤1%) × (1 - 减伤2%) × ...
         × 抗性系数 × 防御系数 × 持续伤害暴击区
```

与常规伤害的唯一区别：**暴击区被替换为持续伤害暴击区**。
- 持续伤害默认不能暴击（持续伤害暴击区 = 1）
- 只有极少数效果能提供持续伤害暴击区（如黑天鹅命途等）

---

#### 6.4.7 欢愉伤害

欢愉伤害是新版本引入的特殊伤害类型，拥有独立的乘区结构：

```
欢愉伤害 = 欢愉倍率 × 基础值 × 特殊独立乘区
         × (1 + 欢愉度%) × (1 + 增笑%)
         × (笑点区 或 好活当赏区)
         × (1 + 易伤%)
         × (1 - 减伤1%) × (1 - 减伤2%) × ...
         × 抗性系数 × 防御系数 × 暴击区
```

各乘区说明：

| 乘区 | 说明 |
|---|---|
| **欢愉倍率** | 技能/效果提供的欢愉伤害倍率 |
| **基础值** | 与角色等级相关，80 级角色固定为 `7535.107` |
| **特殊独立乘区** | 如最终伤害加成等极为特殊的效果，独立乘算 |
| **欢愉度** | 欢愉伤害专属加成乘区（类似常规增伤但独立） |
| **增笑** | 欢愉伤害专属加成乘区，与欢愉度相互独立乘算 |
| **笑点区 / 好活当赏区** | 见下方公式，二者择一使用 |
| **易伤** | 与常规伤害共用 |
| **减伤** | 与常规伤害共用（乘算，下限 1%） |
| **抗性系数** | 与常规伤害共用 |
| **防御系数** | 与常规伤害共用 |
| **暴击区** | 与常规伤害一致：`暴击率 × 暴击伤害 + (1 - 暴击率)`，不暴击时为 1 |

关键规则：
- **欢愉伤害不受常规增伤和虚弱影响**（无增伤区、无虚弱区）
- **欢愉伤害可以暴击**，暴击区计算与常规伤害一致
- 欢愉伤害有专属的**欢愉度**和**增笑**两个独立乘区

**笑点区 / 好活当赏区**：

```
笑点区 = 1 + 笑点 × 5 / (笑点 + 240)
好活当赏区 = 1 + 好活当赏 × 5 / (好活当赏 + 240)
```

二者计算结构相同，区别在于使用的属性值不同：

| 触发场景 | 使用乘区 |
|---|---|
| **欢愉技**造成的欢愉伤害 | 笑点区（使用"笑点"属性） |
| **其余**欢愉伤害 | 好活当赏区（使用"好活当赏"属性） |

---

#### 6.4.7a 欢愉系统机制详解

欢愉系统涉及 4 个独立属性 + 阿哈特殊行动机制，是星铁 2.x 之后引入的复杂系统。

**属性分类**：

| 属性 | 类型 | 来源 | 默认值 |
|---|---|---|---|
| **欢愉度** | 角色面板属性 | 光锥效果、遗器套装效果、角色技能 buff | 0 |
| **增笑** | 角色面板属性 | 光锥效果、遗器套装效果、角色技能 buff | 0 |
| **笑点** | 战斗中动态累积的资源 | 战斗开始/阿哈时刻结束/角色技能效果 | 战斗开始时获得 |
| **好活当赏** | 特殊 buff（TURNS_SELF_END） | 战斗开始/阿哈时刻结束/角色技能效果 | 战斗开始时获得 20 点 |

**笑点机制**：
- 战斗开始时获得等同于**我方欢愉角色数量**的笑点
- 阿哈时刻结束后获得等同于**我方欢愉角色数量**的笑点
- 角色技能效果可获得额外笑点
- 阿哈行动触发阿哈时刻时**清空笑点**
- 当我方获得笑点时，行动条上出现阿哈

**好活当赏机制**：
- 特殊 buff，时效类型为 `TURNS_SELF_END`，默认持续 2 回合
- **非欢愉命途角色无法获得好活当赏**
- 各个好活当赏 buff 的持续时间**独立计算**（不是合并为一个 buff）
- 计算伤害时，计入的好活当赏点数 = 角色身上当前还在持续时间内的所有好活当赏 buff 的点数累加值
- **好活当赏点数无上限**
- 战斗开始时获得 20 点
- 每次阿哈时刻结束后，所有欢愉角色获得等同于**本次阿哈时刻笑点数量**的好活当赏

**阿哈机制**：
- 当我方获得笑点时，行动条上出现阿哈
- 阿哈速度计算公式：
  ```
  阿哈速度 = 80
           + 我方速度最高欢愉角色速度 / 5
           + 我方速度第二高欢愉角色速度 / 10
           + 我方速度第三高欢愉角色速度 / 20
           + 我方速度第四高欢愉角色速度 / 50
  ```
- 阿哈行动时触发**阿哈时刻**：
  1. 解除我方所有欢愉角色的控制类负面状态
  2. 各个欢愉角色按照其欢愉技的**参演编号顺序**释放欢愉技
  3. 清空笑点
  4. 阿哈时刻结束后，所有欢愉角色获得好活当赏（点数=本次笑点数量）+ 笑点（数量=我方欢愉角色数量）

**欢愉伤害限定**：
- 目前**仅有欢愉命途角色**能够造成欢愉伤害
- 欢愉倍率的字段读取方式仍待勘探（nanoka 数据结构未知）

### 6.5 击破机制

- 每个敌人有**韧性值**（toughness）
- 攻击弱点击破韧性：削韧值 = 基础削韧值 × (1 + 弱点击破效率)
- 韧性归零 → 进入**击破状态**：
  - 触发一次性**击破伤害**（公式见 6.4.4）
  - **取消未击破时的 10% 减伤**
  - **怪物自己行动后恢复韧性**（满血恢复，恢复时不会再次触发击破伤害）

**击破恢复细节**：
- 恢复时机：怪物自身的下次行动结束后
- 恢复量：满血恢复（`current_toughness = max_toughness`）
- 恢复时**不会**再次触发击破伤害
- 恢复后 `is_broken` 置 False，重新进入"未击破 10% 减伤"状态

```python
@dataclass
class EnemyState:
    max_toughness: float
    current_toughness: float
    weakness_elements: list[str]   # 弱点属性列表
    is_broken: bool = False

    def reduce_toughness(self, amount: float, element: str) -> bool:
        """返回是否触发击破"""
        if element not in self.weakness_elements:
            return False
        self.current_toughness = max(0, self.current_toughness - amount)
        if self.current_toughness == 0 and not self.is_broken:
            self.is_broken = True
            return True  # 触发击破伤害
        return False

    def get_damage_reduction(self) -> float:
        """返回当前减伤系数（用于伤害公式中的减伤乘区）"""
        if not self.is_broken:
            return 0.10  # 未击破时 10% 减伤
        return 0.0       # 击破后无减伤
```

## 7. 缓存策略

### 三级缓存（简化版）

| 层级 | 机制 | TTL | 用途 |
|---|---|---|---|
| 内存缓存 | Python 模块级变量 | 进程生命周期 | sonata 等共享数据 |
| 磁盘缓存 | `diskcache`（SQLite） | 见下表 | 列表/详情数据 |
| 图标文件 | 本地文件系统 | 永久 | 首次下载后复用 |

### diskcache TTL 策略

| 数据 | TTL | 理由 |
|---|---|---|
| manifest 版本号 | 1 小时 | 版本更新频率低 |
| 列表数据（character.json 等） | 10 分钟 | 对应 wuwa 的 s-maxage=600 |
| 详情数据 | 1 小时 | 详情几乎不变 |
| 中文名映射表 | 1 天 | 变化极少 |
| 图标文件 | 永久 | 不变，手动更新 |

### 实现示例

```python
import diskcache
import httpx

cache = diskcache.Cache('./cache')

async def fetch_json(url: str, expire: int = 600) -> dict:
    cached = cache.get(url)
    if cached is not None:
        return cached
    async with httpx.AsyncClient() as client:
        r = await client.get(url)
        r.raise_for_status()
        data = r.json()
    cache.set(url, data, expire=expire)
    return data
```

## 10. freesr-data.json 角色面板导入

freesr-data.json 是常用的《崩坏：星穹铁道》角色配置导出格式，包含角色（avatars）、遗器（relics）、光锥（lightcones）三块。UI 配置页"导入 freesr-data.json"按钮可导入并计算最终面板。

### 10.1 格式说明摘要

**avatars**（`{avatar_id: {...}}`，data 为空则跳过）：
- `data.rank`：星魂等级（只记录，星魂效果待实现）
- `data.skills`：技能等级映射——`{char_id}001`=普攻、`{char_id}002`=战技、`{char_id}003`=终结技、`{char_id}004`=天赋（freesr id = nanoka id 中间插 0，如 `1504001` ↔ `150401`）；秘技/额外能力/行迹固定 1
- `level`/`promotion`：固定 80/6
- `sp_max`：能量上限；`sp_value`：进战斗初始能量（经 `CharacterUnit.initial_energy` 生效）
- `techniques`：秘技编号（暂不建模）

**relics**（list，按 `equip_avatar` 归属角色）：
- `relic_id` 末位 = 部位（1头部 2手部 3躯干 4脚部 5位面球 6连结绳）
- `relic_set_id`：套装编号（**只记录不计算**，套装效果待实现）
- `main_affix_id`：主词条（按部位映射，见 10.3）
- `sub_affixes`：副词条 `[{count, step, sub_affix_id}]`

**lightcones**（list）：
- `item_id`：与 nanoka 光锥编号对应（如 23056 = 一场谎言的终幕），基础属性经 nanoka 详情拉取
- `level`/`promotion`：固定 80/6；`rank`：叠影数（只记录）

### 10.2 副词条数值表

每个 `sub_affix_id` 有 3 个强化档位；**最终值 = 最低档×count + (第二档-最低档)×step**。

### 10.4 光锥基础值

光锥详情 stats 为晋升段列表，80 级取 promotion=6 行：`基础 = base + add×80`（与角色公式一致），只含 HP/ATK/DEF。

### 10.5 导入流程

1. 配置页"导入 freesr-data.json" → 选文件
2. 解析 avatars/relics/lightcones（`src/core/freesr.py`，纯逻辑可测）
3. 按 char_id 匹配队伍行；已配置但不在队伍中的角色列表提示
4. 光锥详情经 nanoka 异步拉取（diskcache 缓存）；失败按 0 处理并提示
5. **最终面板**（角色基础 + 光锥基础 + 遗器加成）写入队伍表格，覆盖当前数值；技能等级写入全局 SpinBox；`sp_value` 作为初始能量生效

### 10.6 边界与 TODO

- 空配置（avatar 无 data）跳过；遗器/光锥 equip_avatar 无对应角色丢弃
- 导入时角色详情未加载 → 详情加载完成后自动补填
- TODO：遗器套装效果（relic_set_id）、星魂效果（rank）、位面球元素顺序、光锥叠影效果

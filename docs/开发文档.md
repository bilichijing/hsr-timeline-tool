## 1. 项目概述

### 1.1 项目目标

为本《崩坏：星穹铁道》玩家提供一款本地运行的排轴与伤害计算工具，支持：

- 队伍配置（角色 / 光锥 / 遗器 / 词条）
- 回合制排轴编辑（基于行动值 AV 系统）
- 战斗模拟与伤害计算
- 结果分析（DPS、伤害占比、轮次效率）
- 工程存档与分享

### 1.2 运行形态

- **本地桌面应用**（`python ui_main.py`；目标形态：打包为 `.exe` 分发，打包配置尚未落地，见第 8 节）
- **本地 Web 应用**（`python web_main.py` → 浏览器访问 `http://127.0.0.1:8765`）：后端用标准库 HTTP 服务，前端是静态 ES Module；与桌面端共享 `src/core` / `src/api`，功能一一对应（见第 12 节）
- 无需外部服务器资源；Web 端同源访问自己的 API，无 CORS 限制
- 数据从 `static.nanoka.cc` 拉取，本地 diskcache 缓存

### 1.3 与参考项目（wuwa-afyg-tool）的关系

- **参考**：数据层架构思路（manifest 版本管理、列表/详情分离、transform 提纯）
- **不参考**：业务逻辑（实时动作 vs 回合制，完全不同）
- **独立项目**：不共享代码，不共享数据源

### 1.4 关键差异认知

| 维度 | 鸣潮（参考项目） | 星铁（本项目） |
|---|---|---|
| 战斗模型 | 实时动作 | **回合制** |
| 时间轴 | 连续秒数 | **离散行动值（AV）** |
| 速度机制 | 无 | **核心机制**（10000/速度=AV） |
| 资源 | 共鸣能量 | **战技点（SP）**，上限 5 |
| Buff 时效 | 持续秒数 | 持续回合数 |
| 关键指标 | DPS | **轮次伤害 / 0T / 行动效率** |

### 3.2 Manifest 结构（实测）

`GET https://static.nanoka.cc/manifest.json`

返回多游戏统一 manifest，本项目只关心 `hsr` 字段：

```json
{
  "gi": { ... },          // 原神（忽略）
  "hsr": {
    "latest": "4.4.55",
    "available": ["4.4", "4.4.51", "4.4.52", "4.4.53", "4.4.54", "4.4.55"],
    "live": "4.4",
    "new": {
      "character": [1512, 1513],
      "lightcone": [21066, 22008, 23063, 23064],
      "relicset": [],
      "monster": [2022072, 2022082, ...],
      "item": [140630, 140631, ...]
    }
  },
  "ww": { ... },          // 鸣潮（忽略）
  "zzz": { ... },         // 绝区零（忽略）
  "nte": { ... }
}
```

字段说明：
- `latest`：最新版本号（用于拼接数据路径）
- `available`：所有可用版本（可用于版本切换）
- `live`：正式服版本
- `new`：该版本新增内容（用于"新角色"标记）

### 3.3 路径模式

#### 列表（轻量，含中英文名与基础信息）

```
GET https://static.nanoka.cc/hsr/{version}/{entity}.json
```

| entity | 内容 | 示例大小 |
|---|---|---|
| `character` | 角色列表 | ~54 KB |
| `lightcone` | 光锥列表 | ~145 KB |
| `relicset` | 遗器套装列表 | ~92 KB |
| `monster` | 怪物列表 | ~456 KB |

> ✅ 列表 JSON **已包含中文名字段 `zh`**（以及 `ko` / `ja` / `desc`），因此不需要"列表拿英文、详情拿中文"的两级查询：`transform_character_list()` 直接读 `item["zh"]`。

#### 详情（重型，含完整技能/星魂/属性）

```
GET https://static.nanoka.cc/hsr/{version}/zh/{entity}/{id}.json
```

示例：`https://static.nanoka.cc/hsr/4.4/zh/character/1001.json`（约 84 KB）

### 3.5 详情字段（实测）

`zh/character/{id}.json` 顶层字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 中文名 |
| `desc` | string | 角色描述 |
| `chara_info` | object | 阵营、配音等元信息 |
| `rarity` | string | 稀有度枚举（见映射表） |
| `sp_need` | number | 终结技耗能（代码用它近似 `energy_max`） |
| `base_type` | string | 命途枚举（见映射表） |
| `damage_type` | string | 属性枚举（见映射表） |
| `ranks` | object | 星魂（E1-E6，含 `param_list`） |
| `skills` | object | 技能（普攻/战技/终结技/天赋/秘技），`level` 为 `{"1": {"param_list": [...]}}` 结构 |
| `skill_trees` | object | 行迹树（含倍率参数 `status_add_list` 与额外能力 `point_type=3`） |
| `enhanced` | object | 强化技能（如千冶无量忿怒下的强化普攻/终结技） |
| `memosprite` | object | 忆灵数据（风堇小伊卡读 `memosprite.skills[{id}].level`） |
| `stats` | object | 各等级基础属性表（键为突破等级 `"0"~"6"`，80 级取 `"6"`） |
| `relics` | array | 推荐遗器 |
| `lightcones` | array | 推荐光锥 |
| `teams` | array | 推荐队伍 |
| `skin` | object | 皮肤 |

> 详情中 `skills` / `skill_trees` / `ranks` / `memosprite` 在 `CharacterInfo` 里保留**原始 dict**，解析（倍率、削韧、SP/能量、技能类型识别）统一在 `core/skill.py` 完成。

### 3.7 图标资源路径（已实测确认）

图标 URL 由 `src/api/consts.py` 的纯函数拼接（`ASSET_BASE = https://static.nanoka.cc/assets/hsr`）：

| 类型 | 模式 | 说明 |
|---|---|---|
| 角色圆形头像 | `{ASSET_BASE}/avatarroundicon/{角色ID}.webp` | ~10 KB，UI 列表与能量球用 |

`verify_api.py` 的第 7 节会对这 4 类 URL 逐个 `HEAD` 请求验证可访问性；角色选择器下载的头像缓存在 `./cache/icons/`。

### 模块依赖关系

```
ui_main.py
  └─ src/ui/battle_simulator.py
       ├─ src/ui/widgets/*        （依赖 core 与 api）
       ├─ src/core/*              （纯逻辑，不依赖 UI，可独立测试）
       │    ├─ characters/  lightcones/  relics/   （由 simulator 延迟导入触发注册）
       │    └─ 不得导入 PySide6
       └─ src/api/*               （数据获取，不依赖 core 与 UI）

web_main.py
  └─ src/web/server.py
       ├─ src/web/session.py      （队伍状态 + 模拟控制，复用 core）
       ├─ src/web/views.py        （状态 → JSON）
       ├─ src/web/static/*        （浏览器端 ES Module，只与 HTTP API 交互）
       └─ src/core/* 、src/api/*  （与桌面端完全相同的两个下层）
```

两套前端**互不依赖**：桌面端不导入 `src/web`，Web 端不导入 `src/ui`（因此 Web 端不需要安装 PySide6 也能提供服务，只是依赖同一份 `core` / `api`）。

**关键原则**：

2. `api/` 只负责搬运 nanoka 数据，不做业务解释（倍率解析在 `core/skill.py`）。

## 6. 核心设计

### 6.1 行动值（AV）系统

星铁的核心机制。速度决定行动顺序。

#### 基础公式

```
行动值（AV） = 10000 / 速度
```

- 每个角色/怪物初始 AV = 10000 / 自身速度
- AV 最小的先行动
- 行动后 AV 重置为 10000 / 速度，其余角色 AV 减去已消耗值

#### 推条 / 拉条

- **推条**（延后）：AV += X * AV
- **拉条**（提前）：AV -= X * AV（下限 0）
其中X为行动延后/行动提前比例

#### 速度变化时的 AV 调整

速度变化时（如遗器套装、天赋触发），剩余 AV 按以下公式换算：

```
新行动值 = 原行动值 × 新基础行动值 / 原基础行动值 - 新基础行动值 × (提前% - 延后%)
```

其中：
- 基础行动值 = 10000 / 速度
- `提前%` / `延后%` 为本次速度变化同时附带的推拉条比例（无则为 0）

#### 怪物初始 AV

怪物初始 AV 也是 `10000 / 速度`，与角色同规则入队；**`speed <= 0` 的怪物不入队、永不行动**（UI 里的"木桩"即如此，其行为由第 6.8 节的"敌方攻击调度"配置驱动）。

#### 实现要点（`src/core/av_system.py`，157 行）

```python
AV_PER_ACTION = 10000.0

@dataclass
class ActionEntry:
    unit_id: str            # 角色 unit_id / "enemy1" / "__aha__" / "__countdown_x__"
    name: str
    speed: float
    current_av: float       # 距离下次行动的 AV（无 __post_init__，必须显式传入）
    is_monster: bool = False

    def reset_av(self) -> None:
        self.current_av = AV_PER_ACTION / self.speed

@dataclass
class ActionQueue:
    entries: list[ActionEntry] = field(default_factory=list)

    def add(self, entry) -> None                 # 直接 append，不做去重
    def remove(self, unit_id: str) -> None
    def get(self, unit_id: str) -> ActionEntry | None
    def next_actor(self) -> ActionEntry           # AV 最小；空队列 raise RuntimeError
    def advance(self) -> tuple[ActionEntry, float]  # 无参数！返回 (行动者, 消耗 AV)
    def apply_push(self, unit_id: str, rate: float) -> None   # AV ×(1+rate)，无上限钳制
    def apply_pull(self, unit_id: str, rate: float) -> None   # max(0, AV ×(1-rate))
    def update_speed(self, unit_id, new_speed, advance_rate=0.0, delay_rate=0.0) -> None
    def snapshot(self) -> list[tuple[str, str, float, float]]  # UI 显示用，按 AV 升序
```

`advance()` 的语义：先取 AV 最小者为行动者，**所有**单位（含行动者）扣减 `consumed = actor.current_av`，随后行动者 `reset_av()`；调用方自行把 `consumed` 累加到 `total_av`。

`update_speed()` 的官方换速公式：

```
old_base_av = 10000 / 旧速度
new_base_av = 10000 / 新速度
新 AV = 当前 AV × new_base_av / old_base_av - new_base_av × (提前% - 延后%)
current_av = max(0.0, 新 AV)
```

早期文档中的 `advance(av_consumed)`、`apply_push(unit_id: int, av_delta)`、`preview_order(turns)` **均不存在**：推 / 拉条拆成 `apply_push` / `apply_pull` 两个按比例的方法；行动预览由 UI 层 `copy.deepcopy(action_queue)` 静态推演（不改模拟器状态）。

### 6.2 战技点（SP）管理

- 队伍共享，上限 5，初始 3（UI 可配，`BattleSimulator.initial_sp`）
- 普攻 +1（数量取技能 `bp_add`），战技 -1；不消耗 SP 的战技（如千冶）不受 SP 限制
- 某些技能可回复或消耗额外 SP（`Skill.sp_cost` 为负即回复）

```python
class SkillPoint:
    MAX = 5
    INITIAL = 3

    def __init__(self, initial: int | None = None):
        self.current = initial if initial is not None else self.INITIAL

    def consume(self, amount: int = 1) -> bool:
        if self.current < amount:
            return False          # SP 不足，且不修改
        self.current -= amount
        return True

    def recover(self, amount: int = 1) -> int:
        before = self.current
        self.current = min(self.MAX, self.current + amount)
        return self.current - before   # 返回实际回复量

    def can_consume(self, amount: int = 1) -> bool:
        return self.current >= amount
```

UI 侧的拦截分两层：① 角色模块 `skill_deny_reason()` 给出机制原因（如千冶"未开启结界 / 生命 ≤1"）；② 仅当该战技 `sp_cost > 0` 且 `not sp.can_consume(1)` 时提示"战技点不足"。

### 6.3 Buff 系统

#### 时效类型

| 类型 | 说明 | 失效时机 |
|---|---|---|
| `PERMANENT` | 永久 | 战斗结束 |
| `TURNS_SELF_START` | 持续 N 回合（自身回合开始） | 自身回合开始时 -1 |
| `TURNS_SELF_END` | 持续 N 回合（自身回合结束） | 自身回合结束时 -1 |
| `NEXT_ATTACK` | 下次攻击后 | 攻击命中后 |
| `ONCE` | 一次性触发 | 触发后立即失效 |

**TURNS_SELF_END 特殊规则**：若角色在自身回合内获得该类型 buff，则获得 buff 的这个回合结束时，对应 buff 的持续时间**不会减少**（即本次回合结束不扣减，从下一回合才开始扣减）。这意味着 buff 的"持续 N 回合"是从获得后的下一个自身回合开始算的。

实现要点：buff 记录 `applied_in_self_turn` 标志，回合内获得时置 True，首次 `tick_turn_end` 时跳过扣减并清除标志。

#### 叠加规则

| 规则 | 说明 |
|---|---|
| `NO_STACK_SAME_NAME` | 同名 buff 不叠加，刷新时效（匹配键为 `id` **且** `name` 相同） |
| `NO_STACK_SAME_SOURCE` | 同源 buff 不叠加（匹配键为 `source_unit` **且** `name` 相同） |
| `STACK_LIMIT_N` | 同 id 叠层，最多 `max_stacks` 层；满层只刷新时效 |
| `STACK_ALWAYS` | 无限叠加：每次都追加**独立实例、独立计时**（好活当赏即用此规则） |

对 `NO_STACK_*` 两类，命中已有 buff 时取 `duration_count = max(旧, 新)`、`value = max(旧, 新)`（即"不削弱已有的"）。

#### 数据结构

```python
from enum import Enum
from dataclasses import dataclass

class BuffDuration(Enum):
    PERMANENT = "permanent"
    TURNS_SELF_START = "turns_self_start"
    TURNS_SELF_END = "turns_self_end"
    NEXT_ATTACK = "next_attack"
    ONCE = "once"

class StackRule(Enum):
    NO_STACK_SAME_NAME = "no_stack_same_name"
    NO_STACK_SAME_SOURCE = "no_stack_same_source"
    STACK_LIMIT_N = "stack_limit_n"
    STACK_ALWAYS = "stack_always"

@dataclass
class Buff:
    id: str
    name: str
    stat: str                  # 影响的属性（atk_pct / dmg_bonus / elemental_dmg_bonus …）
    value: float               # 数值（百分比已 /100）
    duration_type: BuffDuration
    duration_count: int = 0    # 回合数；PERMANENT 用 -1
    source_unit: str = ""      # 来源单位（时效按它计时，不是持有者）
    stack_rule: StackRule = StackRule.NO_STACK_SAME_NAME
    max_stacks: int = 1
    current_stacks: int = 1
    is_debuff: bool = False    # 供 remove_debuffs()（千冶【百炼骨】解除负面）
    element: str = ""          # stat == "elemental_dmg_bonus" 时指定属性
    applied_in_self_turn: bool = False
```

`BuffManager` 的公开方法：`begin_turn()` / `end_turn()`、`add` / `remove` / `remove_by_name` / `remove_debuffs` / `clear_expired`、`tick_turn_start` / `tick_turn_end` / `tick_attack`、`total_bonus()` / `get_value(stat)`。

回合内实际调用序为 `begin_turn()` → `tick_turn_start()` → … → `tick_turn_end()` → `end_turn()`（`buff.py` 类 docstring 中"end_turn 在 tick_turn_end 之前"的说法与代码不符，以调用序为准）。

### 6.4 伤害公式

星铁伤害分为 **6 类**（`DamageType`）：**常规伤害（`NORMAL`）、击破伤害（`BREAK`）、超击破伤害（`SUPER_BREAK`）、持续伤害（`DOT`）、欢愉伤害（`ELATION`）、真实伤害（`TRUE`）**。其中真实伤害不使用抗性系数与防御系数。

统一入口是 `calculate_damage(ctx: DamageContext) -> float`，按 `ctx.damage_type` 分发到 `calc_normal_damage` / `calc_break_damage` / `calc_super_break_damage` / `calc_dot_damage` / `calc_elation_damage`（真实伤害直接返回 `max(0.0, base_value)`）；未知类型抛 `ValueError`。**没有** `DamageResult` 之类的返回值对象，也不返回各乘区明细。

**暴击判定**：常规伤害与欢愉伤害采用**显式暴击判定**——模拟器为每个伤害段用固定种子独立随机流掷骰（`rng_seed` 可复现），暴击率钳制到 `[0,1]`；击破 / 超击破 / 持续 / 真实伤害不暴击。暴击区 = `1 + 暴击伤害`（不暴击时为 1）。另有 `calc_crit_expectation()`（`1 + 暴击率 × 暴击伤害`）表达期望值，但**当前未被模拟器接入**。

#### 6.4.0 常量与上下文

| 常量 | 值 | 说明 |
|---|---|---|
| `BREAK_BASE_COEFF` | `3767.55` | 击破 / 超击破基础值系数 |
| `ELATION_BASE_LEVEL_80` | `7535.107` | 80 级欢愉伤害基础值 |
| `DEFAULT_RESISTANCE_WEAK` | `0.0` | 弱点属性默认抗性 |
| `DEFAULT_RESISTANCE_NON_WEAK` | `0.20` | 非弱点属性默认抗性 |
| `RESISTANCE_MIN` / `RESISTANCE_MAX` | `-1.0` / `0.90` | 抗性钳制区间 |
| `UNBROKEN_DAMAGE_REDUCTION` | `0.10` | 未击破时的固定减伤 |
| `DAMAGE_REDUCTION_FLOOR` | `0.01` | 减伤乘算下限 |

`DamageContext` 的常用字段：`damage_type`、`element`、`base_value`、`attacker_stats`（`FinalStats`）、`is_weakness`、`is_broken`、`resistance`（`None` → 弱点 0 / 非弱点 0.20）、`res_pen`、`dmg_bonus`（技能 / 属性额外增伤；面板增伤已在 `attacker_stats.dmg_bonus`）、`vulnerability`、`weakness`、`damage_reductions`、`special_multiplier`、`is_crit` / `crit_dmg`、`break_effect` / `break_dmg_bonus`、`toughness_max` / `actual_toughness_reduced`、`super_break_multiplier`、`elation_multiplier` / `is_elation_skill`、`defense_ctx`。

辅助函数：`build_enemy_resistance(weakness_elements, non_weak_resistance=0.20)` 生成抗性字典；`calc_resistance` / `calc_defense` / `calc_damage_reduction` / `calc_crit_zone` / `calc_laugh_zone` 可单独调用做校准。

#### 6.4.1 抗性系数

```
抗性系数 = 1 - 抗性
抗性范围：-100% ≤ 抗性 ≤ 90%
```

- 抗性由"基础抗性 - 减抗"得出，最终值钳制在 [-100%, 90%] 区间
- 弱点属性默认抗性 0%，非弱点属性默认抗性 20%

---

#### 6.4.2 防御系数

**角色攻击敌人时**（敌人等级超过 100 时按 100 计算；扑满须改为 `1.5 × 等级 + 30`）：

```
防御系数 = (角色等级 + 20) / [(角色等级 + 20) + (敌人等级 + 20) × (1 - 减防% - 无视防御%)]
```

**敌人攻击角色时**：

```
防御系数 = (10 × 敌人等级 + 200) / (10 × 敌人等级 + 200 + 角色防御)
```

减防与无视防御为加算关系，共同削减敌人防御占比。

---

#### 6.4.3 常规伤害

```
最终伤害 = 基础值 × 特殊独立乘区
         × (1 + 增伤%) × (1 + 易伤%) × (1 - 虚弱%)
         × (1 - 减伤1%) × (1 - 减伤2%) × (1 - 减伤3%) × ...
         × 抗性系数 × 防御系数 × 暴击区
```

各乘区说明：

| 乘区 | 说明 |
|---|---|
| **基础值** | `攻击力 × 倍率`，攻击力可替换为生命值/防御力等（视技能而定） |
| **特殊独立乘区** | 如最终伤害加成等极为特殊的效果，独立乘算 |
| **增伤** | 描述中带有"我方造成的伤害提升 X%"的效果（属性增伤、通用增伤均属此区） |
| **易伤** | 描述中带有"目标受到的伤害提升 X%"的效果 |
| **虚弱** | 描述中带有"虚弱"的特殊效果，独立乘区 |
| **减伤** | 描述中带有"目标受到的伤害降低 X%"的效果 |
| **暴击区** | **显式判定**：暴击时 `1 + 暴击伤害`，未暴击时为 `1`（期望写法 `1 + 暴击率 × 暴击伤害` 由 `calc_crit_expectation` 提供，未接入模拟器） |

减伤规则：
- **多个减伤为乘算**：例如两个 50% 减伤 ≈ 一个 75% 减伤（0.5 × 0.5 = 0.25）
- **所有减伤乘算后不低于 1%**（下限保护）
- **敌方未被弱点击破时，必定带有 10% 减伤**（击破后此减伤消失）

---

#### 6.4.4 击破伤害

角色击破弱点时，造成的击破伤害：

```
击破伤害 = 击破基础值 × 属性倍率 × 特殊独立乘区
         × (1 + 易伤%)
         × (1 + 击破特攻%) × (1 + 击破增伤%)
         × (1 - 减伤1%) × (1 - 减伤2%) × ...
         × 抗性系数 × 防御系数
```

击破基础值与属性倍率：

```
击破基础值 = 3767.55 × (韧性上限 / 40 + 0.5)
```

| 属性 | 属性倍率 |
|---|---|
| 火、物理 | 2.0 |
| 风 | 1.5 |
| 冰、雷 | 1.0 |
| 量子、虚数 | 0.5 |

关键规则：
- **击破伤害不受常规增伤和虚弱影响**（无增伤区、无虚弱区）
- 但有专门的**击破特攻**和**击破增伤**两个独立乘区
- 击破伤害仍受易伤、减伤、抗性、防御影响

---

#### 6.4.5 超击破伤害

超击破伤害需要通过**角色技能效果**触发，而非自动产生。

**触发条件**（由技能描述决定）：
- 一般情况：攻击**处于弱点击破状态**的敌方目标时触发
- 特殊情况：某些技能效果允许在未击破状态也触发（如大丽花战技"结界持续期间，敌方目标未处于弱点击破状态时承受的削韧值也能够转化为超击破伤害"）

**触发示例**（大丽花天赋）：
> 【共舞者】攻击处于弱点击破状态的敌方目标后，会将本次攻击的削韧值转化为 1 次 60% 的超击破伤害。

**超击破倍率**由触发源（天赋/光锥/技能效果）提供，不同来源倍率不同。

```
超击破伤害 = 超击破基础值 × 超击破倍率 × 特殊独立乘区
           × (1 + 易伤%)
           × (1 + 击破特攻%) × (1 + 击破增伤%)
           × (1 - 减伤1%) × (1 - 减伤2%) × ...
           × 抗性系数 × 防御系数
```

超击破基础值：

```
超击破基础值 = 3767.55 × 实际削韧值 / 10
```

- 与普通击破伤害相同的乘区结构（不受常规增伤和虚弱）
- 基础值取决于**实际削韧值**（本次攻击削减的韧性），而非韧性上限

---

#### 6.4.6 持续伤害

角色造成的持续伤害（DoT，如触电、灼烧、裂伤等）：

```
持续伤害 = 基础值 × 特殊独立乘区
         × (1 + 增伤%) × (1 + 易伤%) × (1 - 虚弱%)
         × (1 - 减伤1%) × (1 - 减伤2%) × ...
         × 抗性系数 × 防御系数 × 持续伤害暴击区
```

与常规伤害的唯一区别：**暴击区被替换为持续伤害暴击区**。
- 持续伤害默认不能暴击（持续伤害暴击区 = 1）
- 只有极少数效果能提供持续伤害暴击区（如黑天鹅命途等）

---

#### 6.4.7 欢愉伤害

欢愉伤害是新版本引入的特殊伤害类型，拥有独立的乘区结构：

```
欢愉伤害 = 欢愉倍率 × 基础值 × 特殊独立乘区
         × (1 + 欢愉度%) × (1 + 增笑%)
         × (笑点区 或 好活当赏区)
         × (1 + 易伤%)
         × (1 - 减伤1%) × (1 - 减伤2%) × ...
         × 抗性系数 × 防御系数 × 暴击区
```

各乘区说明：

| 乘区 | 说明 |
|---|---|
| **欢愉倍率** | 技能/效果提供的欢愉伤害倍率 |
| **基础值** | 与角色等级相关，80 级角色固定为 `7535.107` |
| **特殊独立乘区** | 如最终伤害加成等极为特殊的效果，独立乘算 |
| **欢愉度** | 欢愉伤害专属加成乘区（类似常规增伤但独立） |
| **增笑** | 欢愉伤害专属加成乘区，与欢愉度相互独立乘算 |
| **笑点区 / 好活当赏区** | 见下方公式，二者择一使用 |
| **易伤** | 与常规伤害共用 |
| **减伤** | 与常规伤害共用（乘算，下限 1%） |
| **抗性系数** | 与常规伤害共用 |
| **防御系数** | 与常规伤害共用 |
| **暴击区** | 与常规伤害一致：`暴击率 × 暴击伤害 + (1 - 暴击率)`，不暴击时为 1 |

关键规则：
- **欢愉伤害不受常规增伤和虚弱影响**（无增伤区、无虚弱区）
- **欢愉伤害可以暴击**，暴击区计算与常规伤害一致
- 欢愉伤害有专属的**欢愉度**和**增笑**两个独立乘区

**笑点区 / 好活当赏区**：

```
笑点区 = 1 + 笑点 × 5 / (笑点 + 240)
好活当赏区 = 1 + 好活当赏 × 5 / (好活当赏 + 240)
```

二者计算结构相同，区别在于使用的属性值不同：

| 触发场景 | 使用乘区 |
|---|---|
| **欢愉技**造成的欢愉伤害 | 笑点区（使用"笑点"属性） |
| **其余**欢愉伤害 | 好活当赏区（使用"好活当赏"属性） |

---

#### 6.4.7a 欢愉系统机制详解

欢愉系统涉及 4 个独立属性 + 阿哈特殊行动机制，是星铁 2.x 之后引入的复杂系统。

**属性分类**：

| 属性 | 类型 | 来源 | 默认值 |
|---|---|---|---|
| **欢愉度** | 角色面板属性 | 光锥效果、遗器套装效果、角色技能 buff | 0 |
| **增笑** | 角色面板属性 | 光锥效果、遗器套装效果、角色技能 buff | 0 |
| **笑点** | 战斗中动态累积的资源 | 战斗开始/阿哈时刻结束/角色技能效果 | 战斗开始时获得 |
| **好活当赏** | 特殊 buff（TURNS_SELF_END） | 战斗开始/阿哈时刻结束/角色技能效果 | 战斗开始时获得 20 点 |

**笑点机制**：
- 战斗开始时获得等同于**我方欢愉角色数量**的笑点
- 阿哈时刻结束后获得等同于**我方欢愉角色数量**的笑点
- 角色技能效果可获得额外笑点
- 阿哈行动触发阿哈时刻时**清空笑点**
- 当我方获得笑点时，行动条上出现阿哈

**好活当赏机制**：
- 特殊 buff，时效类型为 `TURNS_SELF_END`，默认持续 2 回合
- **非欢愉命途角色无法获得好活当赏**
- 各个好活当赏 buff 的持续时间**独立计算**（不是合并为一个 buff）
- 计算伤害时，计入的好活当赏点数 = 角色身上当前还在持续时间内的所有好活当赏 buff 的点数累加值
- **好活当赏点数无上限**
- 战斗开始时获得 20 点
- 每次阿哈时刻结束后，所有欢愉角色获得等同于**本次阿哈时刻笑点数量**的好活当赏

**阿哈机制**：
- 当我方获得笑点时，行动条上出现阿哈
- 阿哈速度计算公式：
  ```
  阿哈速度 = 80
           + 我方速度最高欢愉角色速度 / 5
           + 我方速度第二高欢愉角色速度 / 10
           + 我方速度第三高欢愉角色速度 / 20
           + 我方速度第四高欢愉角色速度 / 50
  ```
- 阿哈行动时触发**阿哈时刻**：
  1. 解除我方所有欢愉角色的控制类负面状态
  2. 各个欢愉角色按照其欢愉技的**参演编号顺序**释放欢愉技
  3. 清空笑点
  4. 阿哈时刻结束后，所有欢愉角色获得好活当赏（点数=本次笑点数量）+ 笑点（数量=我方欢愉角色数量）

**欢愉伤害限定**：
- 目前**仅有欢愉命途角色**能够造成欢愉伤害
- 欢愉倍率的字段读取方式仍待勘探（nanoka 数据结构未知）

#### 6.4.8 真实伤害

真实伤害是部分星魂/技能提供的特殊伤害类型（如缇宝 E1）：

```

真实伤害 = max(0.0, 传入的基础伤害值)

```

关键规则：

- **无视防御**：不使用防御系数。
- **无视抗性**：不使用抗性系数。
- **不会暴击**：不进入暴击区。
- **不吃任何增伤**：增伤、易伤、虚弱、击破增伤、欢愉度等乘区全部不参与。
- 真实伤害仍参与战斗总伤害统计，并在伤害明细中标记为“真实伤害”。

### 6.5 击破机制

- 每个敌人有**韧性值**（toughness）
- 攻击弱点击破韧性：削韧值 = 基础削韧值 × (1 + 弱点击破效率)
- 韧性归零 → 进入**击破状态**：
  - 触发一次性**击破伤害**（公式见 6.4.4）
  - **取消未击破时的 10% 减伤**
  - **怪物自己行动后恢复韧性**（满血恢复，恢复时不会再次触发击破伤害）

**击破恢复细节**：
- 恢复时机：怪物自身的下次行动结束后
- 恢复量：满血恢复（`current_toughness = max_toughness`）
- 恢复时**不会**再次触发击破伤害
- 恢复后 `is_broken` 置 False，重新进入"未击破 10% 减伤"状态

```python
@dataclass
class EnemyState:
    max_toughness: float
    current_toughness: float
    weakness_elements: list[str]   # 弱点属性列表
    is_broken: bool = False

    def reduce_toughness(self, amount: float, element: str) -> bool:
        """返回是否触发击破"""
        if element not in self.weakness_elements:
            return False
        self.current_toughness = max(0, self.current_toughness - amount)
        if self.current_toughness == 0 and not self.is_broken:
            self.is_broken = True
            return True  # 触发击破伤害
        return False

    def get_damage_reduction(self) -> float:
        """返回当前减伤系数（用于伤害公式中的减伤乘区）"""
        if not self.is_broken:
            return 0.10  # 未击破时 10% 减伤
        return 0.0       # 击破后无减伤
```

> 实际 `EnemyState`（`src/core/simulator.py`）比上述示意多若干字段：`level` / `speed` / `resistance: dict[str, float]` / `def_reduce` / `vulnerability` / `crit_dmg_taken` / `crit_dmg_taken_by_unit` / `max_hp` / `current_hp` / `buff_mgr`。减伤系数不直接由 `EnemyState` 提供，而是由 `damage.calc_damage_reduction()` 从 `ctx.is_broken` 与 `ctx.damage_reductions` 计算。

### 6.6 能量系统

```python
def recover_energy(char, amount, *, fixed=False) -> float
```

- **普通回能** × `(1 + energy_regen)`；`fixed=True` 表示"固定回能"（游戏文案带"固定"字样，如不死途天赋 8 点，不吃能量恢复效率）。
- 回能上限为 `base_stats.energy_max`（由 `sp_need`（终结技耗能）近似，缺省 100）。
- **溢出能量**：当 `overflow_energy_max > 0` 时（千冶【百炼骨】），回能超出上限的部分积攒到 `overflow_energy`；施放终结技时清空溢出并把对应能量补回当前能量。
- 能量从不足恢复到满时，自动 `buff_mgr.remove_debuffs()` 解除自身负面效果（千冶【百炼骨】）。
- 终结技耗能：优先取 `Skill.energy_cost`，缺省用 `_get_energy_cost()` 兜底 90；`execute_ultra()` 会先校验 `char.energy >= energy_cost`。

### 6.7 我方生命与治疗模型

- `CharacterUnit.current_hp`：`setup()` 时初始化为 `final_stats().hp`（满血）。上限取 `final_stats().hp`，因此生命上限类 buff（风堇秘技 / 雨过天晴）变化时会按**剩余生命比例**重算当前生命。
- `sim.heal(healer, target, amount, *, source="skill") -> (实际治疗量, 计入累计治疗的原始治疗量)`：
  - 治疗乘区 = `1 + 治疗者 outgoing_heal + 受治疗者 incoming_heal`（**加算**）；
  - 实际治疗钳制到当前生命缺口，溢出部分仍计入返回值中的"原始治疗量"（风堇用它累积"累计治疗数值"）；
  - 会分发遗器套装的 `on_heal` 钩子（125 女武神【甘霖】即依赖它）。
- 敌方攻击我方：`伤害 = 攻击力 × 防御系数`，其中 `防御系数 = (10×敌人等级 + 200) / (10×敌人等级 + 200 + 角色防御)`；随后依次分发 `on_incoming_damage`（可返回减免后的伤害，如千冶【千锻魂】减伤 50% / 致命免死）与 `on_damage_taken`（受击后触发，如千冶 E6 充能）。

### 6.8 敌方模型与敌方攻击调度

- 敌方支持 **1~5 个目标**，UI 中所有敌人**共享**韧性 / 弱点 / 等级 / 抗性 / 生命配置（`unit_id = "enemy1".."enemy5"`，`name = "木桩"`，`speed = 0.0`）。
- 抗性由 `build_enemy_resistance(弱点属性列表, 非弱点抗性)` 生成：弱点属性 0%，其余取配置值（默认 20%）。
- 敌人 HP 归零即**死亡离场**：移出 `enemies` 与行动队列，并分发 `on_enemy_dead` 让模块清理引用。
- **敌方攻击调度**（`EnemyAttack`，UI"敌方攻击"表）：因为木桩速度为 0 不会自然行动，所以用配置强行排程：

  ```python
  EnemyAttack(total_av=120.0,          # 累计总行动值推进到该值时强制行动
              source_enemy_index=0,    # 由第几个敌人释放（0-4）
              attack=1200.0,           # 本次攻击力
              target_indices=[0, 1],   # 命中的角色下标（多选）
              energy_recover=10.0)     # 为受击角色恢复的能量
  ```

  `setup()` 会为每条配置插入一个 `"__enemy_attack_N__"` 调度单位，`current_av = total_av`；到点后对每个目标结算伤害与回能，分发 `on_enemy_act`，然后从队列移除。

### 6.9 行动条上的特殊单位

| 单位 ID | 类型 | 说明 |
|---|---|---|
| 角色 `unit_id` | 玩家控制 | `_character_act` → `_resolve_skill` |
| `"enemy1".."enemy5"` | 怪物（`is_monster=True`） | 行动后满韧性恢复；分发 `on_enemy_act` |
| `"__aha__"` | 阿哈 | 笑点 > 0 时入队，行动触发阿哈时刻（见 6.4.7a） |
| `"__countdown_<uid>__"` | 行动条倒计时 | 由 `sim.add_countdown(owner, speed=, name=)` 插入（如千冶无量忿怒 70 速倒计时），行动时触发所属模块 `on_countdown` 后移除；同角色重复添加会刷新位置 |
| `"__enemy_attack_N__"` | 敌方攻击调度 | 见 6.8 |

`sim.is_auto_unit(actor)` 统一判定"自动行动单位"（怪物 / 阿哈 / 倒计时 / 敌方攻击调度），UI 对这些单位不需要玩家选择技能，交互模式下会自动 `step()`。

## 7. 缓存策略

### 三级缓存（现行）

| 层级 | 机制 | 位置 / TTL | 用途 |
|---|---|---|---|
| 内存缓存 | Python 模块级变量 | 进程生命周期 | `_PIXMAP_CACHE`（图标 QPixmap）等 |
| 磁盘缓存 | `diskcache`（SQLite） | `./cache/`，TTL 见下表 | manifest / 列表 / 详情 |
| 本地文件 | 文件系统 | `./cache/icons/`（永久）、`./cache/team_config.json` | 头像图标、队伍配置 |

### diskcache TTL 策略

| 数据 | TTL | 理由 |
|---|---|---|
| manifest 版本号 | 1 小时 | 版本更新频率低 |
| 列表数据（character / lightcone / relicset / monster） | 10 分钟 | 与站点 `s-maxage=600` 对齐 |
| 详情数据 | 1 小时 | 详情几乎不变 |
| 中文名映射表（`CacheTTL.ZH_NAMES`） | 1 天 | **已不需要**：列表含 `zh` 字段，仅作历史预留 |
| 图标文件 | 永久 | 不变；`download_icon()` 发现文件已存在即跳过 |

### 实现示例（现行 `api/client.py`）

```python
import diskcache, httpx
from pathlib import Path

CACHE_DIR = Path("./cache")
CACHE_DIR.mkdir(parents=True, exist_ok=True)     # 模块导入时创建
cache = diskcache.Cache(str(CACHE_DIR))

async def fetch_json(url: str, *, expire: int = CacheTTL.LIST,
                     use_cache: bool = True) -> dict | list:
    if use_cache:
        cached = cache.get(url)
        if cached is not None:
            return cached
    try:
        r = await get_client().get(url)
        r.raise_for_status()
        data = r.json()
    except (httpx.RequestError, httpx.HTTPStatusError) as e:
        stale = cache.get(url, expired=True)      # 网络失败回退过期缓存
        if stale is not None:
            logger.warning("网络失败，使用过期缓存: {} | {}", url, e)
            return stale
        raise
    if use_cache:
        cache.set(url, data, expire=expire)
    return data
```

> 关键点：缓存的 key 是**完整 URL**（含版本号），因此版本升级后旧缓存自然失效、不会串数据。

## 10. freesr-data.json 角色面板导入

freesr-data.json 是常用的《崩坏：星穹铁道》角色配置导出格式，包含角色（avatars）、遗器（relics）、光锥（lightcones）三块。UI 配置页"导入 freesr-data.json"按钮可导入并计算最终面板。

### 10.1 格式说明摘要

**avatars**（`{avatar_id: {...}}`，data 为空则跳过）：
- `data.rank`：星魂等级 0~6（已接入星魂效果模块）
- `data.skills`：技能等级映射——`{char_id}001`=普攻、`{char_id}002`=战技、`{char_id}003`=终结技、`{char_id}004`=天赋（freesr id = nanoka id 中间插 0，如 `1504001` ↔ `150401`）；秘技/额外能力/行迹固定 1
- `level`/`promotion`：固定 80/6
- `sp_max`：能量上限；`sp_value`：进战斗初始能量（经 `CharacterUnit.initial_energy` 生效）
- `techniques`：秘技编号（暂不建模）

**relics**（list，按 `equip_avatar` 归属角色）：
- `relic_id` 末位 = 部位（1头部 2手部 3躯干 4脚部 5位面球 6连结绳）
- `relic_set_id`：套装编号（已实现 freesr 数据中出现的**全部八套**：110 / 115 / 125 / 132 / 308 / 319 / 320 / 326；其中 308 / 319 / 320 / 326 是只有 2 件套效果的位面饰品）
- `main_affix_id`：主词条（按部位映射，见 10.3）
- `sub_affixes`：副词条 `[{count, step, sub_affix_id}]`

**lightcones**（list）：
- `item_id`：与 nanoka 光锥编号对应（如 23056 = 一场谎言的终幕），基础属性经 nanoka 详情拉取
- `level`/`promotion`：固定 80/6；`rank`：光锥叠影等级 1~5（已实现 23056 / 23059 / 23038 / 23042 四张的叠影效果）

### 10.5 导入流程

1. 配置页"导入 freesr-data.json" → 选文件

4. 光锥详情经 nanoka 异步拉取（diskcache 缓存）；失败按 0 处理并提示
5. **最终面板**（角色基础 + 光锥基础 + 遗器加成 + 光锥第一句常驻加成）写入队伍表格，覆盖当前数值；技能等级写入全局 SpinBox；`sp_value` 作为初始能量生效
   - 实现上是**两步**：`freesr.compute_panel_breakdown()` 返回 `(白字 BaseStats, 绿字 StatBonus, FinalStats)`（不含光锥第一句），再由 `freesr.apply_lightcone_panel_bonus(白字, 绿字, 光锥ID, 光锥params)` 把第一句加成**写进绿字**并返回最终面板。UI 会把白字 / 绿字分别存进 `_RowCharData.panel_white_base` / `panel_green_bonus`
   - 光锥第一句“使装备者 xx 提高 xx%”的常驻效果会直接计入局外面板，例如：
     - 23056：暴击率提高
     - 23059：生命上限提高
     - 23038：暴击伤害提高
     - 23042：速度提高
   - 进入战斗后，光锥模块不再重复挂载这些第一句常驻 buff，避免面板与战斗双重计算。

**挂载顺序**（`BattleSimulator.setup()`）：**光锥模块 → 遗器模块 → 角色模块**（保证秘技等进战动作能吃到光锥 / 遗器常驻 buff），随后用最终速度重算行动队列。角色模块的进战钩子分**两阶段**分发：先全体 `on_battle_start_setup`（光环 / 常驻 buff / 治疗 / 能量），再全体 `on_battle_start`（进战伤害，如秘技）——这样无论站位如何，秘技都能吃到全队进战 buff。遗器模块按 `relic_set_counts[set_id] >= 2` 才会实例化。

**事件钩子**（模拟器用 `getattr` 分发，未实现的钩子即跳过）：

| 钩子 | 时机 | 用途 |
|---|---|---|
| `on_battle_start_setup(sim, char)` | 战斗开始·第一阶段 | 初始化状态、全队光环 / 常驻 buff / 治疗 / 能量、读星魂与行迹 |
| `on_battle_start(sim, char)` | 战斗开始·第二阶段 | 秘技伤害等进战动作 |
| `on_turn_start(sim, char)` / `on_turn_end` | 角色回合开始 / 结束（buff tick 之后） | 自身回合计时（缇宝结界、风堇 buff 到期） |
| `on_resolve_skill(sim, char, skill_type, skill)` | 回合行动 / 插队终结技前 | **替换**技能（无量忿怒下普攻 / 终结技强化版）或返回 `None` **拒绝**施放（千冶战技限制）；返回原 skill 表示不参与 |
| `on_skill_cast(sim, char, skill, action, target, log)` | 伤害结算前 | 标记目标、消耗生命、清空无伤害技能的误解析 effects |
| `on_attack_hit(sim, attacker, skill, target, effect, damage, log, action_token)` | 每次命中后（削韧 / 击破结算后） | 天赋触发（千冶充能、不死途追击、缇宝附加伤害记录） |
| `on_skill_end(sim, char, skill, action, target, log)` | 本行动日志入列后 | 追加伤害段、终结技追击链（日志顺序在此正确） |
| `on_post_skill(sim, char, skill, action, target, log)` | 所有模块 `on_skill_end` 与追击链之后 | "行动完全结束"才结算的效果（缇宝附加伤害取被击中目标中生命最高者、风堇雨过天晴忆灵技） |
| `on_countdown(sim, char, log)` | 行动条倒计时行动 | 结界解除（无量忿怒倒计时） |
| `on_enemy_act(sim, enemy, log)` | 怪物 / 敌方攻击行动后 | 敌方回合计时（煞火缠身剩余回合 -1、光锥【炼狱】倒计时、风堇自动治疗判定） |
| `on_enemy_dead(sim, enemy)` | 敌人死亡离场后 | 清理模块对它的引用（饲饵转移目标、煞火缠身移除） |
| `on_incoming_damage(sim, char, amount, source, ctx) → float` | 我方即将受伤 | 返回减免后的伤害（千冶【千锻魂】减伤 50%、致命免死） |
| `on_damage_taken(sim, char, amount, source, ctx)` | 我方受到伤害后 | 星魂等触发（千冶 E6 受击充能、千锻魂给攻击者上煞火缠身） |
| `on_memo_skill_end(sim, owner)`（仅光锥） | 忆灵技完整结算后 | 23042 的易伤与附加伤害 |
| `on_heal(sim, owner, healer, target, amount, raw, actual, source)`（仅遗器） | 治疗结算后 | 125 女武神【甘霖】 |
| `enemy_buffs(sim, enemy) → list[tuple[str, str]]` | UI 查询 | 返回本模块施加的敌方 debuff（名称, 描述）逐条展示 |
| `skill_deny_reason(sim, char) → str \| None` | UI 交互按战技前 | 战技被拒原因（未开结界 / 生命≤1），弹窗提示 |

模块工具函数：`module_params(skill, N, default)` —— 读 `skill.params[N-1]`，越界返回默认值（数据缺失时模块应 no-op 并在日志备注中说明）。

### 11.2 行动令牌（按"行动"粒度去重的核心）

`BattleSimulator.action_token`：**每次技能施放（`_resolve_skill`）递增**。一次行动内的主伤害 + 模块 `on_skill_end` 追击链共享同一令牌；模块可用 `sim.begin_new_action()` 主动开启新行动（不死途终结技追击链、天赋追击、千冶追加战技均独立）。

**冻结令牌**：`on_attack_hit` 分发时模拟器传入**冻结的 `action_token`**（伤害循环开始时快照）——分发循环内其他模块 `begin_new_action()` 修改全局令牌不影响本次命中的去重键。模块按"行动"去重必须用该参数（读 `sim.action_token` 会在连锁（令牌交替 T/T+1/T+2）时误判）。

去重示例：
- 千冶天赋充能"每次攻击 +1"：战技 5 段（同一令牌）计 1 点；不死途终结技本体 1 点 + 追击链整体 1 点；不死途天赋追击、千冶追加战技各 1 点
- 不死途天赋"受到攻击回 8 能量"：按行动计（战技 5 段命中只回一次），充能不足时回能照常、追击不触发

### 11.3 行动条倒计时

`sim.add_countdown(owner_char, speed=, name=)`：在行动序列插入倒计时单位（如千冶无量忿怒倒计时，固定 70 速），同角色已有倒计时时刷新位置。倒计时行动时触发所属模块 `on_countdown`（结界解除）后从队列移除。`sim.is_auto_unit(actor)` 统一判定怪物/阿哈/倒计时为自动行动单位（UI 交互空格自动执行）。

### 11.4 最小 HP 模型与敌方易伤

- `CharacterUnit.current_hp`：当前生命值（模块在 `on_battle_start` 初始化为面板生命上限；生命消耗/回复由模块管理，上限取 `final_stats().hp`）。千冶战技/终结技消耗生命，不足降至 1；生命 ≤1 无法施放战技
- `EnemyState.vulnerability`：敌方易伤（模块增量式累加/撤销，如千冶【煞火缠身】受伤 +30%）；`def_reduce` 同样改为各模块维护贡献值（不死途增量式，与煞火缠身共存）

### 11.5 技能解析细节

- `skill.py`：`bp_need=-1` 语义——普攻 = 回复（数量 `bp_add`）；**非普攻 = 不消耗**（千冶战技"不消耗战技点"、终结技不回复 SP）
- 千冶生命倍率伤害：`on_skill_cast` 把 effects[0].base_stat 修正为 `"hp"`（parse 默认 atk）；150703 终结技本体无伤害（#1 是生命消耗），effects 清空防误伤
- 技能无效行动（`on_resolve_skill` 返回 None）：回合照常消耗，返回"无法施放（技能受限）"日志（与战斗结束区分，UI 不误判）

### 11.6 双技能类型标记

`DamageRecord.secondary_skill_type`：同时属于两种技能类型的伤害（主类型 + 第二种）。千冶天赋触发的战技"本次战技视为追加攻击"：每段伤害 `skill_type=FOLLOW_UP` + `secondary_skill_type=SKILL`——统计/未来 buff 判定（战技伤害提高 / 追加攻击伤害提高）两者兼顾。`deal_damage(..., secondary_skill_type=...)` 透传。

### 11.7 千冶•刃机制要点（mortenax.py）

- 伤害全部基于**生命上限**（base_stat="hp"）；普攻 25%（强化 50%）、战技 36%+4×12%、强化终结技 210%
- 战技/终结技消耗生命（10%/20%），不足降至 1；生命 ≤1 或未开结界无法施放战技（`on_resolve_skill` 拒绝 + UI 弹窗）
- 终结技开结界：全体【煞火缠身】（减防 20% + 易伤 30%，2 个敌方回合，`on_enemy_act` 计时）、无量忿怒 buff（暴击率 +20%、暴伤 +30%）、70 速倒计时（回合开始结界解除）
- 无量忿怒下：普攻换 150708（50%）、终结技换 150714（210%，耗能 160）、战技解锁
- 天赋充能：结界期间每次攻击（按行动，含自身）+1，封顶 9；达 9 且生命 >1 → 消耗充能、回能量（等级参数，10 级 = 25）、**额外施放战技**（独立行动、双技能类型标记、战技回能 30）；生命 ≤1 时充能保留
- 【百炼骨】行迹：战斗开始/结界解除时能量不足 75% 恢复至 75%（比例从行迹 param_list[0] 读取）
- 倒计时 70 速（142.86 AV 后行动）：100 速千冶开结界后通常轮不到结界内行动（游戏真实表现）

### 11.8 缇宝机制要点（tribbie.py）

- 同谐/量子，能量上限 120；伤害全部基于**生命上限**（base_stat="hp"）
- 【神启】：战技/秘技进战获得，持续 3 回合（自身回合开始 -1）；我方全体**全属性抗性穿透**提高（12%→30%）
  - 抗性穿透新乘区：`FinalStats.res_pen` → `DamageContext.res_pen` → `calc_resistance` 最终抗性 = 抗性 − 穿透（钳制 [-100%, 90%]）
  - 神启以 buff（`stat="res_pen"`，TURNS_SELF_START）加到全体我方角色，`source_unit`=缇宝 → 只有缇宝回合开始时 tick 扣减
- 终结技开结界：全体 #1（15%）生命上限量子伤害 + 敌方受伤提高 #2（15%，vulnerability 增量式）+ 持续 #4（2）回合（缇宝回合开始 -1，`on_turn_start` 钩子扣减，归零解除并撤销易伤/A2）
- 结界附加伤害：我方目标攻击（**按行动计**，含缇宝自己）后，对被攻击目标造成 #3（6%）生命上限量子附加伤害；**并入触发它的那次行动**（不单独成行动、不建独立日志），攻击类型为【附加伤害】`SkillType.ADDED`（不属于普攻/战技/终结技/追加攻击），伤害来源为缇宝
- **附加伤害 ≠ 攻击**：`deal_damage` 的 `is_attack=False` 分支不触发 `on_attack_hit` 钩子与 NEXT_ATTACK buff tick——不死途天赋、千冶充能等"攻击后"系效果不受附加伤害影响（曾因不死途追击 `begin_new_action` 改全局令牌导致缇宝终结技后不死途误触发 2 次追击，已回归测试覆盖）；目标按敌方当前 HP 最高者选取
- 天赋：我方其他角色施放终结技后，缇宝全体追加攻击 #1（9%）生命上限量子伤害（独立行动 + 追击回能 5）；每角色最多 1 次，缇宝终结技重置
- 行迹（point_type=3，按名称前缀匹配读取，UI 通路走兜底常量）：
  - A2【长翅膀的玻璃球】：结界期间缇宝生命上限 = 我方全体生命上限之和的 9%（hp_flat buff）。**已实现动态重算**：`on_turn_start` / `on_skill_end` / `on_post_skill` 都会调 `_sync_a2_hp()`（由 `TestA2Dynamic` 覆盖）
  - A4【岔路旁的小石子】：战斗开始回 30 能量；我方**其他**目标攻击（按行动）后回 1.5 能量
  - A6【城墙外的羊羔儿】：天赋追击后缇宝增伤 72%/层，最多 3 层，持续 3 回合（dmg_bonus buff，STACK_LIMIT_N）
- 新钩子：`on_turn_start`（角色回合开始，模块做自身回合计时）在 `_character_act` 的 buff tick 后分发

### 11.9 UI 集成

- 交互模式：`is_auto_unit` 统一处理怪物 / 阿哈 / 倒计时 / 敌方攻击调度的自动行动；按战技前查 `skill_deny_reason` 弹窗，再查 SP
- 充能徽章：模块类属性 `CHARGE_STYLE`（`"dots"` 圆点 / `"text"` 文字）与 `CHARGE_MAX`——不死途 3 个圆点，千冶红色文字 "x/9"（上限可被 E2 改写为 `charge_limit`）
  - **没有 `charge` 字段的模块不显示徽章**：缇宝与风堇均无资源徽章（风堇的"资源"是小伊卡，见 11.10）
- 甘特图：倒计时行动点（青灰）、敌方攻击（红）、行高/间距可调（`LANE_HEIGHT` / `LANE_GAP`）、刻度与行动点裁剪到甘特图区域（标签 / 标题不裁剪）、同 AV 事件纵向排列
- 敌方 buff 弹窗：由各模块的 `enemy_buffs()` 逐条提供（不死途【饲饵】、千冶【煞火缠身】、缇宝【结界】、光锥【影噬】/【炼狱】等）

### 11.10 风堇机制要点（hyacine.py）

- 记忆 / 风，`CHAR_ID = "1409"`；**无资源徽章**（未定义 `CHARGE_STYLE` / `CHARGE_MAX`，也没有 `charge` 字段）
- 技能 ID：普攻 `140901`、战技 `140902`、终结技 `140903`、天赋 `140904`、秘技 `140907`；忆灵侧走 `char.memosprite_raw`：忆灵技 `1140901`、召唤回能 `1140905`
- **轻量忆灵"小伊卡"**：不进入行动队列，只作为模块状态（`memosprite_alive` / `memosprite_max_hp` / `memosprite_hp`）
  - 召唤：战技 / 终结技时召唤，生命上限 = 风堇最终生命上限 × 天赋 #1（默认 50%），满血；召唤即回能，**首次**召唤额外回能
  - 生命上限跟随：风堇生命上限变化时（见下）按比例同步
- **治疗乘区**：走 `sim.heal()`，实际治疗 = 基础治疗 × `(1 + outgoing_heal + incoming_heal)`（加算，`TestHealing` 覆盖）；溢出部分仍计入"累计治疗数值" `cumulative_healing`
- **技能效果**：
  - 战技：治疗我方全体（`生命上限 × #1 + #2`）+ 治疗小伊卡，日志备注"治疗"
  - 终结技：治疗全体 + 小伊卡，并施加【雨过天晴】——全体生命上限提高（`#3` 百分比 + `#4` 固定值，`#5` 回合），日志备注"治疗·雨过天晴"
  - 秘技（在 `on_battle_start_setup` 阶段结算）：全体治疗（`#1` + `#2`）+ 全体生命上限提高 `#3` 持续 `#4` 回合
- **生命上限 buff 的实现**（`_apply_max_hp_delta`）：先快照全队剩余生命比例与小伊卡血量比例 → 移除旧 `hp_pct` / `hp_flat` buff → 按新上限按比例回填生命；小伊卡上限 = 风堇最终生命上限 × 继承比，血量按旧比例回填。buff 为 `PERMANENT`，**由模块手动移除**（回合数由 `sunny_turns` / `tech_turns` 自管）
- **自动治疗**（`_check_auto_heal`，数值注释为"用户确认的自动治疗数值"）：
  - 触发点：`on_turn_start`（**每个角色**回合开始）、`on_enemy_act`、`on_post_skill`、忆灵技结算后
  - 判定：比较 HP 快照找出掉血的我方目标；一次判定只扣小伊卡 **4%** 上限生命（扣到 0 则小伊卡离场且本次不治疗）
  - 治疗量：`风堇生命上限 × 2% + 20`，对每个掉血目标生效（`source="memosprite"`）；【雨过天晴】期间额外对我方全体再治疗一次
- **天赋·治疗时小伊卡增伤**：每次有效治疗叠 1 层（上限 3 层）、持续 2 回合，每层 +40% 增伤，忆灵技结算后计时 -1
- **忆灵技**（`_execute_memo_skill`）：伤害基础值 = `累计治疗数值 × 忆灵技 #1`（默认 10%），以 `fixed_base_value` 对我方**全体敌人**造成风属性常规伤害（`skill_type = MEMO_DNSKILL`，削韧 0，`actor_name = "小伊卡"`）；结算后累计治疗按 `(1 - #2)` 衰减；随后**直接调用光锥钩子 `on_memo_skill_end`**（专供 23042 愿虹光永驻天空，是本项目唯一由角色模块主动分发的光锥钩子）
- **雨过天晴的额外忆灵回合**：风堇技能完全结算后（`on_post_skill`），若【雨过天晴】仍在且小伊卡存活，立即再放一次忆灵技
- 未建模：小伊卡不进入行动条（无独立 AV）；`MEMO_AUTO = "1140903"`（忆灵天赋自动治疗）为声明未用的常量

### 11.11 遗器套装模块（relics/）

## 12. Web 前端

目标：在**保留原有桌面端全部功能**的前提下，提供一套浏览器界面；两端共享 `src/core` 与 `src/api`，因此数值口径完全一致。

### 12.1 技术选型

| 层 | 方案 | 选型理由 |
|---|---|---|
| 后端 | 标准库 `http.server.ThreadingHTTPServer` + 手写路由 | 本地单用户工具，接口只有十几个；避免为 1 个用户引入 FastAPI / Flask + ASGI server 的依赖与生命周期管理，也避免打包体积增加 |
| 传输 | JSON（`Content-Type: application/json`） | 前端不需要二进制协议 |
| 前端 | 原生 ES Module + 手写 CSS（`src/web/static/`） | **无 Node、无构建步骤、无 CDN**：改完刷新即可看到效果，仓库不引入 npm 生态与锁文件 |
| 图表 | 甘特图 Canvas 2D、饼图内联 SVG | 零依赖；Canvas 便于缩放 / 平移 / 命中测试，SVG 便于 hover 提示 |
| 弹窗 | 原生 `<dialog>` + `showModal()` | 焦点管理与 ESC 关闭由浏览器负责 |
| 图标 | 直接引用 nanoka 资源 URL | 后端不再下载 / 落盘图标（桌面端仍缓存到 `./cache/icons`） |

### 12.2 分层

```
浏览器（static/js）
   │  fetch /api/*            ← 只发命令、只渲染返回的状态
   ▼
src/web/server.py  路由 + 静态资源（ThreadingHTTPServer）
   ▼
src/web/session.py 唯一会话：队伍行 + 配置 + 模拟器 + 快照栈
   ▼
src/web/views.py   状态 → JSON 视图（格式化、甘特 lanes、饼图、汇总）
   ▼
src/core/* + src/api/*     与桌面端完全相同的下层
```

**关键约定**：前端的 `app.js` 不保存业务状态，只保存"当前 Tab / 选中日志行"；所有写操作（`POST`）都返回**完整状态**，前端整体重渲染，因此不存在前后端状态漂移。

### 12.3 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 返回 `static/index.html` |
| GET | `/static/*` | 静态资源（带路径穿越防护） |
| GET | `/api/meta` | 面板字段 / 命途属性映射 / 遗器部位与主副词条表 / 输入限制 |
| GET | `/api/state` | 完整状态（rows / config / sim / result / message） |
| GET | `/api/catalog/characters` | 角色目录（含图标 URL） |
| GET | `/api/catalog/lightcones` | 光锥目录 |
| GET | `/api/catalog/relicsets` | 遗器套装目录（含 2/4 件套文案、内圈标记） |
| POST | `/api/team/name`、`/api/team/rank`、`/api/team/panel` | 行内编辑 |
| POST | `/api/team/character` | 选角色（拉详情 → 重算面板，保留装备） |
| POST | `/api/team/lightcone` | 选光锥 / 叠影 / 清除 |
| POST | `/api/team/relics` | 设置 6 部位遗器（拉套装效果 → 重算面板） |
| POST | `/api/config` | 局部更新 enemy / battle / skill_levels / enemy_attacks |
| POST | `/api/import/freesr` | 导入 freesr-data.json |
| POST | `/api/reset` | 重置队伍 |
| POST | `/api/sim/start`、`advance`、`act`、`ultra`、`rewind`、`target`、`run` | 交互模拟与一次性模拟 |

返回约定：`POST` 成功 → `{"message": "提示文本", "state": {...}}`；业务错误 → HTTP 400 + `{"error": "中文原因"}`（前端弹 toast）。

### 12.4 会话状态与持久化

- `Row`：与桌面端 `_RowCharData` 对齐（`char_id` / `path` / `element` / `stats80` / `skills_raw` / `skill_trees_raw` / `ranks_raw` / `memosprite_raw` / 光锥 6 字段 / 遗器 4 字段 / `panel_white_base` / `panel_green_bonus` / `cells`）。
- `Session.apply_panel()`：`compute_panel_breakdown()` → `apply_lightcone_panel_bonus()` → `apply_relic_set_panel_bonus()`，与桌面端 `_apply_row_panel()` 完全一致；`panel_white_base` / `panel_green_bonus` 拍平后存 JSON。
- `Session.build_characters()`：镜像桌面端 `_collect_config()`，包含「白字 / 绿字拆分 + `_sync_flat` 反解表格面板值 + 把 `elemental_dmg_bonus` / `follow_up_*` 带进战斗」的全部细节；未加载真实数据的行回退 `core.character_factory.make_preset_character()`。
- `Session.start_sim()/advance()/act()/ultra()/rewind()`：调用顺序与桌面端 `_interactive_*` 一致（`pending_av_actor` 去重、`skill_deny_reason`、SP 检查、`snapshot()`/`restore()`、回溯后保留 `old_logs` 灰显）。
- 持久化：`./cache/web_state.json`（`version: 1`），每次写操作后保存；读取失败时回退默认值（不阻断启动）。

### 12.5 前端文件

| 文件 | 职责 |
|---|---|
| `js/api.js` | fetch 封装（`GET`/`POST`，错误统一抛 `Error(中文)`） |
| `js/ui.js` | 转义、数字格式化、toast、模态框、二次确认、事件委托 |
| `js/pickers.js` | 目录缓存 + 通用选择器（角色 / 光锥含叠影 / 遗器套装）+ 6 部位遗器编辑器（含副词条实时数值） |
| `js/views.js` | 侧栏（能量球 / SP / 敌人 / 攻击预览）+ 7 个 Tab 渲染 + Canvas 甘特图 + SVG 饼图 |
| `js/app.js` | 启动、Tab 切换、全局事件（含配置表单 / 表格编辑）、键盘（空格 / Q / E / 1~4） |
| `css/app.css` | 深色主题（与桌面端 `theme.py` 配色一致）、响应式布局 |

### 12.6 与桌面端的差异

| 项 | 桌面端 | Web 端 |
|---|---|---|
| 打开方式 | `python ui_main.py` | `python web_main.py` → 浏览器 |
| 图标 | 下载到 `./cache/icons` | 直接引用 URL |
| 角色 / 装备选择 | 双击列 + 模态 | 点击列 + `<dialog>` |
| 配置存档 | `./cache/team_config.json`（v6） | `./cache/web_state.json`（v1），两者互不影响 |
| 面板编辑 | 双击单元格 → 输入 | 直接编辑输入框（失焦生效） |
